## 结构化决策模型与图像输入

新增 `gpt-6-luna-decisions`、`clef-omni` 和 `microsoft-decision-1`，统一通过 Decisions 专用接口调用。GPT-6 Luna Decisions 单次请求最多支持 16 张图片，Clef Omni 最多支持 4 张；Microsoft Decision 1 支持文本与 JSON，不支持图片。图片可使用 HTTPS 地址或 PNG、JPEG、WebP data URL；图片处理失败时请求会返回错误，不会静默丢弃图片后继续处理。该接口当前不支持音频或视频输入。

请求结构、模型限制、调用示例与价格见[结构化决策（GPT、Clef 与 Microsoft）](/api-reference/gpt-6-luna-decisions)。

</Update>

<Update label="2026-10-09" tags={["kunpo-v9.32", "Tripo", "3D", "修复"]}>

## Tripo 参考图片上传修复

参考图片上传统一自动转为 URL，新增模型无需调整上传方式；修复 v3.5 单图和多图贴图任务的图片输入问题。客户端仍可提交 Base64 或 data URL；图片转存失败时接口会返回明确错误，并停止提交生成任务。

用法见 [Tripo 3D 与模型处理](/api-reference/tripo-3d#模型贴图)。

</Update>

<Update label="2026-10-09" tags={["kunpo-v9.31", "计费"]}>

## 模型价格信息同步

同步 Gemini 3.1 Flash-Lite 与 Grok 4.6 的文本对话计价说明。Claude Sonnet 5.5 的缓存读取价格修正为 USD 0.10 / 百万 tokens；其余输入、输出及缓存写入单价不变。Claude Messages usage 仅提供汇总缓存写入量时，按 5 分钟缓存写入单价结算；提供具体 TTL 分项时按对应单价结算。Grok 4.6 的完整输入长度达到 200,000 tokens（含）时，全请求按长上下文档计费。费用按实际用户分组倍率结算，调用参数无需调整。

详见[文本对话计费说明](/api-reference/text-chat)与 [Claude Sonnet 5.5](/api-reference/claude-sonnet-55)。

</Update>

<Update label="2026-10-09" tags={["kunpo-v9.30", "安全"]}>

## GPT-6.1 Sol、个人访问令牌与安全更新

`gpt-6.1-sol` 已开放，可通过 Chat Completions 与 Responses 调用该模型，提供 1,050,000-token 上下文和最高 128,000-token 输出。Responses 支持推理档位和函数工具流程。模型固定按 Standard 计费；缓存读取按完整输入长度分档，≤272,000 tokens 为 USD 0.10 / 百万 tokens，超出时为 USD 0.20 / 百万 tokens。字段、工具流程和完整价格见 [GPT-6.1 Sol](/api-reference/gpt-6-1-sol)。

个人访问令牌（PAT）可按权限范围管理，并可单独查看和撤销。新建令牌的明文仅在创建时显示；令牌管理操作需要安全验证。旧版管理 `access token` 自 v9.30 上线起有 30 天过渡期，期满停用，请迁移使用 PAT；普通 `sk-` 模型调用 API Key 不受影响。PAT 不能替代网页登录会话；浏览器登录绑定、用量授权和图片资产管理仍需网站会话及相应安全验证。升级后请重新登录；此前复制的产物链接若失效，可从任务详情重新获取。

</Update>

## Tripo 贴图与模型处理接口

新增独立贴图、网格分割与智能分割、部件补全、重拓扑、模型导入和格式转换；同时支持 Gaussian Splat、文生图与图生图、多视图编辑、文件上传/预签名上传和批量任务查询。已有 3D 生成和动画路径继续可用。

生成、处理、上传和查询共 22 个原生端点。新增模型沿用积分计费；开启密钥模型白名单时，请加入要调用的模型 ID。任务输入必须为本账号可用的任务或文件引用。

完整参数、限制、示例和费用见 [Tripo 3D 与模型处理](/api-reference/tripo-3d)。

</Update>

<Update label="2026-09-07" tags={["行为变更"]}>

## 异步提交状态改为 queued

图片与旧视频异步接口的提交响应 `status` 从 `submitted` 改为 `queued`。若客户端依赖旧值，请更新判断逻辑；结合 HTTP 状态码与 `task_id` 判断是否成功提交。

轮询接口仍使用 `data.status` 和大写枚举，终态为 `SUCCESS` / `FAILURE`。详见[异步任务状态](/api-reference/image-generation/asynchronous#任务状态)。

</Update>
