## 3D 生成支持多图参考

新增两个接口，多张参考图终于能一起用了：

```
POST https://llm.ziy.cc/tripo/v3/generation/multiview-to-model   # 多视角生 3D
POST https://llm.ziy.cc/tripo/v3/generation/image-to-multiview   # 单图出四视角图
```

多视角出模把视角图放进 `inputs`，键取 `front` / `left` / `back` / `right`（`front` 必填、至少 2 个视角），
每个视角同样支持直接传 Base64，网关自动转存图床。也可以传扁平的 `images` 数组，按前左后右顺序映射。

只有一张图时可以先用 `image-to-multiview` 让模型补出四视角（固定 10 credits），
再把该任务的 `task_id` 填进 `inputs` 复用，不必把图片回传一遍。

计费上 `multiview-to-model` 与图生 3D 同价，**视角数量不影响价格**。

五个模型 `v3.1-20260211`、`v3.0-20250812`、`v2.5-20250123`、`P1-20260311`、`P2-20260801` **走多视角接口都支持多图**。

<Note>
  原有的 `image-to-model` 始终只接受一张参考图（`input` 是字符串），往它传多张图会返回 400
  `file is required for image_to_model`——**五个模型一个都不例外，`P2-20260801` 也不支持**。多图请走新接口。
</Note>

详见 [3D 模型生成（Tripo）](/api-reference/tripo-3d)。

</Update>

## 修复异步图生图传 Base64 报 502

`Image-GI` / `Image-GI2` 通过异步接口 `POST /v1/images/tasks` 传 Base64 参考图时会返回 502，
上游报「URL 格式不合法」；同一张图走同步接口 `/v1/images/generations` 一直是正常的。

现在两条接口行为一致：`images` 数组里可以直接放 Base64、`data:` URL 或公网 URL，
网关会把 Base64 转存到 KUNPO 图床后再交给上游。单图字段 `image` 同样适用。

</Update>

## 新增 3D 模型生成（Tripo）

新增五个 3D 生成模型，异步任务模式，输出 GLB 模型文件和渲染预览图：

```
POST https://llm.ziy.cc/tripo/v3/generation/text-to-model    # 文生 3D
POST https://llm.ziy.cc/tripo/v3/generation/image-to-model   # 图生 3D
GET  https://llm.ziy.cc/tripo/v3/tasks/{task_id}             # 查询任务
GET  https://llm.ziy.cc/v1/tasks/{task_id}/artifacts         # 列出并下载产物
```

可用模型为 `v3.1-20260211`、`v3.0-20250812`、`v2.5-20250123`、`P1-20260311`、`P2-20260801`。
`model` 必须写完整 ID，简写会返回 400。

计费按上游实际消耗结算：提交时预估冻结，完成后按真实用量多退少补，任务失败全额退回。

图生 3D 的 `input` 可以直接传本地图片的 Base64（或 `data:` URL），网关会自动转存到 KUNPO 图床后再交给上游，
不需要自己准备图片外链。也支持直接传公网 URL，但带防盗链的图床（例如 Pexels）会被上游判为无法访问。

完整参数、轮询与下载示例见 [3D 模型生成（Tripo）](/api-reference/tripo-3d)。

</Update>

## 异步任务提交响应的 status 改为 queued

提交异步任务（生图、视频）后，响应里的 `status` 由 `submitted` 改为 `queued`：

```json
{
  "task_id": "task_xxxxxxxxxxxx",
  "status": "queued"
}
```

<Warning>
  如果你的代码用 `status == "submitted"` 判断提交是否成功，需要改掉。
  推荐**只用 HTTP 状态码和 `task_id` 是否存在**来判断提交结果，不要依赖提交时的 `status` 取值。
</Warning>

轮询接口不受影响，仍是 `data.status` 加大写枚举，终态为 `SUCCESS` / `FAILURE`。
完整说明见 [异步任务与结果查询](/api-reference/image-generation/asynchronous#任务状态)。

## 修复同步生图偶发连接中断

启用图片转存的同步生图请求（如 `Image-GPT2` 配 `response_format: url`）在 HTTP/2 下
偶发 `curl: (92)` 或 `RST_STREAM` 报错——响应内容其实完整正确，但客户端随后报错。

根因是响应头里的 `Content-Length` 与转存后的实际长度不一致，已修复。
