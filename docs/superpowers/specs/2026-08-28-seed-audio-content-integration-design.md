# Seed Audio 线上内容增量整合设计

## 目标

将线上旧页 `/api/audio-generation/` 中仍有价值、但当前项目尚未收录的内容，增量整合到唯一维护页 `api-reference/seed-audio.mdx`，不回退当前页面已有的实测结论与完整参数说明。

## 方案选择

1. **增量合并到现有页面（采用）**：保留当前结构，只补充线上旧页的独有信息，改动最小且符合单一信息源约定。
2. 整页替换：会丢失当前页面的兼容性、参考图片实测和已验证范围，不采用。
3. 新增旧版页面：会造成音频参数、计费和示例重复，不采用。

## 内容与位置

只编辑 `api-reference/seed-audio.mdx`：

- 在接口说明处明确音频生成应调用 `/v1/audio/speech`，不要调用 `/v1/chat/completions`。
- 在计费提示中补充按最长 120 秒预扣、按 `original_duration` 结算并退回差额的说明。
- 将“最简调用”整理为 `CodeGroup`，收录 cURL、Python `requests` 和 OpenAI SDK 三种等价示例。
- 在参考图片提示中说明：若公开图片站点阻止上游抓取，应改用 `image_data` Base64。

不修改 `docs.json`、其他 MDX、发布配置或构建产物。

## 内容边界

- 现有参数表、原生参数示例、参考资源示例、错误响应和已验证范围继续作为主内容。
- 不把线上旧页整段复制进来，不重复计费表或响应约定。
- 线上旧页作为本次内容基线；本次不发起真实音频生成，不验证计费或上游抓取行为。

## 验收

1. 新增信息出现在对应章节，三种最简示例使用相同端点、模型和 API Key 占位符。
2. MDX 组件闭合、代码块可渲染，仓库无新增重复音频页面。
3. `git diff --check`、Mintlify 配置校验和 broken-links 检查通过。
4. 不提交、不推送、不发布；现有无关未跟踪文件保持不变。
