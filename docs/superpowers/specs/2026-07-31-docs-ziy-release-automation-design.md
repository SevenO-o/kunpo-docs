# `docs.ziy.cc` 文档发布与验收流程设计

## 目标

把本仓库的 Mintlify 文档发布固化为 Agent 可执行的受控流程。用户发出“发布 docs.ziy.cc”指令后，Agent 在不读取或写入任何密钥的前提下，完成静态构建、服务器版本切换、线上验收和可回滚报告。

本设计只覆盖 `https://docs.ziy.cc`，不触碰 KUNPO 平台容器、`st.ziy.cc` 或其他域名。

## 已确认事实与工作假设

- 文档源码目录是本仓库根目录，框架为 Mintlify。
- 当前构建命令为 `npx mintlify export --output <zip>`；导出的 zip 可作为静态站点发布。
- 服务器别名为 `dify`，OpenResty 当前将 `docs.ziy.cc` 的站点根目录指向 `/opt/1panel/www/sites/docs.ziy.cc/index`。
- 用户修改文档后可能尚未提交 Git；发布应允许此状态，但必须在报告中标记源码提交号和脏工作树状态。
- 发布只由用户明确指令触发，不监听 Git 提交，也不设置定时自动发布。

## 方案选择

采用“仓库内配置 + 原子版本切换”的方案。

每次发布先在本地构建并校验，再上传到服务器的独立版本目录。仅当远端产物完整且校验通过时，才把 OpenResty 现有的 `index` 入口原子切换到该版本。失败时保留原线上版本，不修改入口。首次接入会先把现有 `index` 内容迁入一个带时间戳的历史版本，再建立入口软链接。

不采用直接覆盖 `/opt/1panel/www/sites/docs.ziy.cc/index` 的方式，因为中途上传失败会令线上站点处于半更新状态，也无法可靠回滚。

## 交付文件与职责

| 文件 | 职责 |
| --- | --- |
| `DEPLOYMENT.md` | 面向 Agent 的发布契约：触发语句、边界、禁止项、标准步骤、故障处理和报告格式。 |
| `deployment/sites/docs.ziy.cc.conf` | 不含密钥的站点发布配置：域名、SSH 别名、构建命令、入口页面、远端站点目录与保留版本数。 |
| `scripts/release-docs.sh` | 唯一发布入口：预检、构建、上传、远端暂存、版本切换、验收与报告生成。默认不接受隐式发布。 |
| `scripts/verify-docs-release.sh` | 可单独执行的只读验收：检查远端入口、当前版本、OpenResty 配置和公网关键页面。 |
| `artifacts/releases/`（Git 忽略） | 每次发布生成的脱敏 JSON 报告；只记录版本 ID、时间、提交号、脏树标记、校验结果和 HTTP 状态，绝不记录密钥或 Cookie。 |

## 发布数据流

1. 用户明确发出发布指令。Agent 首先显示本次源码路径、域名和将执行的站点配置，确认配置只指向 `docs.ziy.cc`。
2. 发布脚本记录当前 Git 提交号和是否存在未提交改动；未提交文档只产生警告，不阻断发布。
3. 在本地临时目录执行 Mintlify 导出，验证 zip 可解压、根目录含 `index.html`、首页和关键文档页面存在。
4. 生成不可重复的 release ID（UTC 时间戳加短提交号或 `dirty` 标记），将解压产物上传至服务器的暂存目录。
5. 远端验证暂存版本的 `index.html` 和预期关键页面；成功后把版本移动到 `releases/<release-id>`。
6. 原子更新站点 `index` 软链接。切换前入口保持旧版本；切换后无需重启 Mintlify 或 KUNPO 容器。若 OpenResty 配置变更，先执行配置测试，只有通过后才 reload OpenResty。
7. 通过服务器本机请求和公网 HTTPS 请求验证首页、`/quick-start`、`/api-reference/overview`；每项必须返回 `200`，并检查首页正文含预期的本次构建标识或与远端 `index.html` 的摘要一致。
8. 生成脱敏发布报告。验收失败时自动把入口切回前一版本，并将最终状态记为失败或已回滚。

## 服务器目录约定

```text
/opt/1panel/www/sites/docs.ziy.cc/
├── index -> releases/<release-id>     # OpenResty 当前站点入口
├── releases/
│   ├── legacy-<timestamp>/             # 首次接入时保存现有线上内容
│   └── <release-id>/                   # 每个已验证版本
└── log/                                # 保持现有 OpenResty 日志位置
```

脚本只允许操作此站点目录中的 `index`、`releases` 和专用暂存目录；不得修改证书目录、OpenResty 全局配置、KUNPO 容器、Docker Compose 或服务器环境变量。

## 失败与回滚

- 本地导出、压缩包检查或关键页面检查失败：不上传、不切换，报告本地失败原因。
- 上传或远端暂存校验失败：删除本次暂存目录，不改线上入口。
- 切换后的服务器本机或公网检查失败：立即把 `index` 恢复到上一个已验证版本，并报告回滚结果。
- 未找到上一个版本：停止并保留当前入口，要求用户处理；绝不猜测或删除现有线上内容。
- 只保留最近五个已验证版本；清理只能发生在新版本验收成功之后，且永远不删除当前版本和上一个回滚版本。

## 安全边界

- SSH 仅使用本机既有的 `dify` 凭据；脚本、配置和报告均不存储私钥、密码、token、Cookie 或证书内容。
- 仅接受预先登记的域名和站点路径，不接受发布指令中临时拼接的远端路径。
- 用户未发出明确发布指令时，Agent 只能运行只读构建或验收，不得上传、切换或 reload 服务。
- 不把构建压缩包或完整 HTML 产物提交 Git。

## 验证与验收标准

实现完成后至少验证：

1. `npx mintlify export` 成功，且产物 zip 可完整解压。
2. 发布脚本的 dry-run 不产生 SSH 写入，不修改服务器入口。
3. 配置缺失、错误域名、构建失败和远端关键文件缺失会在切换前停止。
4. 使用安全的本地临时目录模拟一次版本准备，证明入口切换命令只作用于已配置站点目录。
5. `verify-docs-release.sh` 对当前线上站点通过：远端入口存在、OpenResty 配置仍为 `docs.ziy.cc`、公网首页与两条关键页面均为 `200`。
6. 每次真实发布后报告包含 release ID、源码提交、脏树标记、构建摘要、远端版本、各检查状态和回滚状态。

## 非目标

- 不新增 Git 提交自动发布、CI/CD 平台、定时巡检或告警服务。
- 不改文档内容、Mintlify 页面设计或 API 文档信息架构。
- 不迁移 `docs.ziy.cc` 到 KUNPO 容器，也不修改 DNS、证书或 CDN 设置。
