# Qwen Image 3.0 Pro（qwen-image-3.0-pro）

请求时使用 API 模型名 `qwen-image-3.0-pro`；Qwen Image 3.0 Pro 仅为展示名称。

## 适用场景

- 复杂图文排版、中文文字渲染和界面素材生成
- 通过图片与文本组合完成多模态文生图或图生图

## 调用方式

Qwen 仅支持[同步图片生成](/api-reference/image-generation/synchronous)。上游限制为 **1 RPM**，单张通常约需 50–60 秒；请将请求频率控制在每分钟最多 1 次。

## 最小同步示例

```bash
curl -X POST https://llm.ziy.cc/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-image-3.0-pro",
    "prompt": "一只橘猫坐在窗边，柔和的晨光，写实摄影"
  }'
```

## 多模态请求结构

多模态请求使用 `input.messages`。当前仅支持单轮对话，因此 `messages` 必须是只含一个对象的数组；该对象必须包含 `role` 和 `content`。

| 属性 | 类型 | 必填 | 规则 |
|------|------|:----:|------|
| `input.messages` | array | 是 | 仅含一个消息对象 |
| `messages[0].role` | string | 是 | 必须为 `user` |
| `messages[0].content` | array | 是 | 消息内容数组，按文生图或图生图场景组合 |

### `content` 组合方式

| 场景 | `content` 内容 |
|------|-----------------|
| 文生图（T2I） | 仅包含一个 `{ "text": "..." }` 对象 |
| 图生图（I2I） | 包含 1–3 个 `{ "image": "..." }` 对象和 1 个 `{ "text": "..." }` 对象；数组顺序定义多图的图像顺序 |

`image` 可以是 HTTP/HTTPS 公网 URL，或 `data:{MIME_type};base64,{base64_data}` 格式的 Base64 数据。图生图支持 JPG、JPEG、PNG、BMP、TIFF、WEBP 和 GIF；建议图片宽高均在 384–2048 像素之间，单张不超过 10 MB。需要将本地图片转换为可访问地址时，可[获取临时公网 URL](https://help.aliyun.com/zh/model-studio/get-temporary-file-url)。

`text` 是描述期望内容、风格和构图的正向提示词，支持中英文，建议不超过 4500 Token。每个 `content` 数组只允许一个 `text` 对象；缺少或传入多个都会报错。

## 多模态文生图

多模态请求仍需保留顶层 `prompt`。文生图时，`content` 只放文本。

```bash
curl -X POST https://llm.ziy.cc/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-image-3.0-pro",
    "prompt": "使用多模态文本生成一张水墨风格的山水画，不添加文字。",
    "input": {
      "messages": [{
        "role": "user",
        "content": [
          { "text": "生成一张水墨风格的山水画，不添加文字。" }
        ]
      }]
    },
    "parameters": {
      "prompt_extend": false,
      "n": 1,
      "watermark": false,
      "size": "1024*1024"
    }
  }'
```

## 多模态图生图

将主体图、风格图和编辑指令依次放入 `input.messages[0].content`。图片对象必须在文本对象前，并在文本中说明图 1、图 2 的职责。

```bash
curl -X POST https://llm.ziy.cc/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-image-3.0-pro",
    "prompt": "使用多模态内容中的图1主体和图2风格，仅进行风格转换，不添加文字。",
    "input": {
      "messages": [{
        "role": "user",
        "content": [
          { "image": "data:image/jpeg;base64,<主体图>" },
          { "image": "data:image/png;base64,<风格图>" },
          { "text": "图1为主体参考，图2为风格参考。仅进行风格转换，保留图1的主体与构图，不添加文字。" }
        ]
      }]
    },
    "parameters": {
      "prompt_extend": false,
      "n": 1,
      "watermark": false,
      "size": "1024*1024"
    }
  }'
```

<Note>
  图片可以使用公网 URL 或 Base64 / data URL。该形态返回标准 `data[].url`；实际输出尺寸以返回图片为准。不要使用顶层 `image` 或 `images` 字段替代多模态结构。
</Note>

## 尺寸与质量规则

| 项目 | 规则 |
|------|------|
| 普通顶层 `size` | 仅接受 `宽x高`，例如 `1234x789` |
| 不支持的格式 | `1:1`、`16:9` 等比例格式会返回 HTTP `400`，提示 `Expected format: '<width>*<height>'` |
| 未传 `size` | 由模型根据提示词自动推荐分辨率，实际尺寸以返回图片为准 |
| 像素面积 | `262,144`（512×512）至 `4,194,304`（2048×2048） |
| 宽高比 | `1:8` 至 `8:1` |
| `quality` | 不支持，建议不要传入 |

多模态请求中的 `parameters.size` 使用 `1024*1024`；普通顶层 `size` 仍使用 `宽x高`。两种格式不能混用。

## 限制与常见误用

- Qwen 仅支持同步接口，不能用于异步任务接口。
- 多模态请求必须保留顶层 `prompt`。
- 顶层 `image` / `images` 对 Qwen 不产生可靠的参考图效果；请使用 `input.messages[].content[]`。
- `quality` 不会映射到上游请求，也不会影响生图质量或输出分辨率。
