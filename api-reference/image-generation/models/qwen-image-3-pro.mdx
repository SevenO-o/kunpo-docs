<span id="qwen-image-3.0-pro" />

适合复杂图文排版、中文小字与界面素材生成，支持文生图和多模态图生图。请求中的 API 模型名为 **`qwen-image-3.0-pro`**。

**调用方式**：仅支持[同步调用](/api-reference/image-generation/synchronous)，不支持 `/v1/images/tasks` 异步接口。

<Note>
  单张通常约需 50–60 秒；上游限制为 **1 RPM**，请将请求频率控制在每分钟最多 1 次。
</Note>

## 最小示例

```bash
curl -X POST https://llm.ziy.cc/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-image-3.0-pro",
    "prompt": "一只橘猫坐在窗边，柔和的晨光，写实摄影"
  }'
```

请求完成后，从 `data[0].url` 获取图片。公共请求与响应说明见[同步调用](/api-reference/image-generation/synchronous)。

## 多模态文生图

同一个 `/v1/images/generations` 同步接口支持多模态请求。文生图时，`content` 只放文本；顶层 `prompt` 仍需保留。

```bash
curl -X POST https://llm.ziy.cc/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-image-3.0-pro",
    "prompt": "使用多模态文本生成一张水墨风格的山水画，不添加文字。",
    "input": {
      "messages": [{
        "role": "user",
        "content": [
          { "text": "生成一张水墨风格的山水画，不添加文字。" }
        ]
      }]
    },
    "parameters": {
      "prompt_extend": false,
      "n": 1,
      "watermark": false,
      "size": "1024*1024"
    }
  }'
```

<Note>
  这是当前 KUNPO Gateway 的多模态请求形态。`parameters.size` 使用 `*` 连接；普通顶层 `size` 仍使用 `宽x高`。
</Note>

## 图生图

将主体图、风格图和编辑指令依次放入 `input.messages[0].content`。图片对象放在文本对象前面，并在文本中说明图 1、图 2 的职责。不要使用顶层 `image` / `images` 字段替代此结构。

### `image` 输入要求

每个图片对象使用 `image` 字段，值为图像的公网 URL 或 data URL。图生图支持传入 **1–3 张**图像；多图时，`content` 数组中的先后顺序就是图像顺序，请在随后的文本指令中明确各图的作用。

| 项目 | 要求 |
|------|------|
| 支持格式 | JPG、JPEG、PNG、BMP、TIFF、WEBP、GIF |
| 建议分辨率 | 宽和高均为 384–2048 像素 |
| 单张大小 | 不超过 10 MB |

支持以下两种输入形式：

- **公网 URL**：支持 HTTP 和 HTTPS。
- **data URL**：格式为 `data:{MIME_type};base64,{base64_data}`，不支持不带 `data:` 前缀的裸 Base64。

将下方 `<主体图>`、`<风格图>` 替换为各自图片文件的完整 Base64 编码，或将整个 `image` 值替换为公网图片 URL。

```bash
curl -X POST https://llm.ziy.cc/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-image-3.0-pro",
    "prompt": "使用多模态内容中的图1主体和图2风格，仅进行风格转换，不添加文字。",
    "input": {
      "messages": [{
        "role": "user",
        "content": [
          { "image": "data:image/jpeg;base64,<主体图>" },
          { "image": "data:image/png;base64,<风格图>" },
          { "text": "图1为主体参考，图2为风格参考。仅进行风格转换，保留图1的主体与构图，不添加文字。" }
        ]
      }]
    },
    "parameters": {
      "prompt_extend": false,
      "n": 1,
      "watermark": false,
      "size": "1024*1024"
    }
  }'
```

<Note>
  图片可以使用公网 URL 或 data URL；实际输出尺寸以返回图片为准。
</Note>

## 尺寸与参数

| 项目 | 规则 |
|------|------|
| 格式 | 仅接受 `宽x高`，例如 `1234x789` |
| 不支持的格式 | 不支持 `1:1`、`16:9` 等比例格式；传入会返回 HTTP `400`，提示 `Expected format: '<width>*<height>'` |
| 未传 `size` | 由模型根据提示词自动推荐分辨率，实际尺寸以返回图片为准 |
| 像素面积 | `262,144`（512×512）至 `4,194,304`（2048×2048） |
| 宽高比 | `1:8` 至 `8:1` |

<Note>
  多模态 Qwen 请求仍需保留顶层 `prompt`；图片与多模态文本放在 `input.messages[].content[]`。当前 Gateway 示例中的 `parameters.size` 使用 `1024*1024` 形式，普通顶层 `size` 仍使用 `宽x高`，详见本页多模态示例。
</Note>

`quality` 不受支持，不会影响本模型的生图质量或输出分辨率，建议不要传入。

多模态示例中的 `parameters` 使用 `prompt_extend: false`、`n: 1`、`watermark: false` 和 `size`。这些示例值不代表其他取值均已验证。

## 常见问题

**为什么参考图没有生效？** 使用本页图生图结构，把图片放在 `input.messages[].content[].image`；顶层 `image` / `images` 不能替代它。

**为什么传入 Base64 后失败？** Qwen 的图片字段需要公网 URL 或完整 data URL，不支持裸 Base64。

**为什么尺寸写法有两种？** 普通顶层 `size` 使用 `宽x高`；多模态 `parameters.size` 使用 `宽*高`。不要传 `16:9` 等比例字符串。
