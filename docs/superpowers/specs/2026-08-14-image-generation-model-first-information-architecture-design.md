# 图片生成文档：模型优先的信息架构设计

## 目标

让读者能先按所选模型找到可用能力和正确示例，同时保留同步、异步接口的公共协议说明，避免把相同的认证、请求与轮询规则复制到每个模型页。

本次设计解决的重点是模型间已经存在的行为差异：GI/GI2 的比例语义、GPT Image 2 的自定义像素尺寸、Qwen 的多模态输入，以及 Midjourney 的一次多图返回。它不改变网关接口、模型代号、价格或已验证的模型行为。

## 范围与边界

- 重构范围限于 `api-reference/image-generation/` 下的 Markdown/MDX 内容与 `docs.json` 中该分组的导航。
- 保留现有概览、同步、异步页面的 URL；新增模型页而不重命名已有页面，避免破坏外部链接。
- 不重新进行付费模型调用；参数和能力的描述沿用已验证的 Gateway 行为。需要新增或更新实测结论时，另行取得明确授权和预算范围。
- 不修改认证、API 路径、SDK、发布配置或静态站点发布流程。

## 最终导航

```text
图片生成
├─ 概览与选型
├─ 模型指南
│  ├─ Nano Banana Pro（Image-GI）
│  ├─ Nano Banana 2（Image-GI2）
│  ├─ GPT Image 2（Image-GPT2）
│  ├─ Qwen Image 3.0 Pro（qwen-image-3.0-pro）
│  └─ Midjourney（Image-MI）
├─ 同步调用协议
└─ 异步任务协议
```

模型指南的页面路径使用展示名而非内部代号，例如 `api-reference/image-generation/models/nano-banana-pro.mdx`；页面标题和每个示例中的 `model` 字段同时标出对应 API 代号。这样 URL 便于阅读，而请求仍使用实际可调用的模型名。

## 页面职责

| 页面 | 保留或新增的内容 | 不应承载的内容 |
|---|---|---|
| `overview.mdx` | 模型选型卡片、能力/计费汇总、共通认证与存储约定、跳转入口 | 各模型完整参数规则和大段示例 |
| `synchronous.mdx` | 同步端点、通用请求/响应格式、适用模型标记、指向模型示例的链接 | Qwen 等单一模型的完整请求体 |
| `asynchronous.mdx` | 提交、查询、状态、轮询的公共协议，以及支持异步的模型范围 | 模型专属尺寸或质量规则 |
| `models/*.mdx` | 单模型能力、限制、最小可运行示例、专属参数、尺寸/质量规则、常见误用 | 同步响应格式或异步轮询流程的完整复制 |

每个模型页以固定顺序编写：适用场景 → 支持的调用方式 → 最小示例 → 参数与尺寸/质量规则 → 限制和常见误用 → 相关协议链接。需要同步或异步时，只链接公共协议页并附上适用标记。

## 内容迁移

| 现有内容 | 目标位置 | 处理方式 |
|---|---|---|
| 模型列表、选择建议、价格表 | 概览 | 压缩为选型和计费汇总；每行链接模型页 |
| GI/GI2 的比例映射、`auto` 状态和不匹配回退 | 两个 Nano Banana 模型页 | 各页写其适用映射；如规则完全相同，以同一短表和相互链接避免漂移 |
| GPT Image 2 的合法自定义 `WxH`、像素/比例边界及 `quality` | GPT Image 2 页 | 保留为 Gateway 合约，不夸大为全量实测 |
| Qwen 的 `input.messages[].content[]`、`parameters`、`1024*1024` 与图生图示例 | Qwen 页 | 从同步页整体迁入；同步页改为链接 |
| Midjourney 的四图返回和模型限制 | Midjourney 页 | 从现有概览或接口示例中集中整理 |
| 同步端点、响应和通用参数 | 同步协议页 | 只保留一次完整定义；模型页不重复 |
| 异步创建、查询、状态与 Python 工作流 | 异步协议页 | 只保留一次完整定义；模型页标明是否支持 |

## 链接与兼容性

- 既有 `overview`、`synchronous`、`asynchronous` URL 保持不变。
- 已有 Qwen 多模态锚点改为永久重定向不可用的情形不存在于静态 MDX；因此同步页保留一个简短的兼容提示和模型页链接，并在概览中替换指向新页。
- 所有模型页均从概览卡片、模型指南导航和适用协议页可达；不依赖读者搜索获得入口。
- `docs.json` 将“模型指南”作为图片生成分组中的嵌套组，置于概览后、协议页前。

## 验收与回归检查

1. 全仓搜索每个 API 模型代号，确保示例中的 `model` 值未被展示名替换。
2. 检查同一规则只有一个完整维护点：模型专属规则在模型页，协议规则在同步/异步页。
3. 检查新增链接和锚点；`docs.json` 中的每个新增页面都能被 Mintlify 导出。
4. 运行 `git diff --check`、敏感信息扫描和 `npx mintlify export --output <temporary-zip>`，并校验 ZIP 完整性。
5. 使用本地预览检查概览、五个模型页、同步协议页和异步协议页的导航、代码块与移动端目录展示。

## 实施顺序

1. 新建模型目录和五个模型页，先迁移现有事实，不补写未验证能力。
2. 将概览压缩为选型与汇总入口，并将模型名称链接到详情页。
3. 将同步页的 Qwen 专属内容替换为链接；异步页只保留公共工作流。
4. 更新 `docs.json` 导航并运行链接、导出和本地预览验证。
5. 由内容负责人核对每个模型页的能力、计费和示例，再单独提交实施改动。
