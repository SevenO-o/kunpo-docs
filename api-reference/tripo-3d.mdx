title: "3D 模型生成（Tripo）"
description: "基于 Tripo API v3 的三维模型生成，支持文生 3D、图生 3D、多视角生 3D 与单图出四视角，输出 GLB 模型和渲染预览图。"
---

3D 生成是异步任务：先提交任务拿到 `task_id`，轮询到完成后再取产物。出模任务的产物有两个——GLB 模型文件和一张渲染预览图。

接口路径与 Tripo 官方 v3 保持一致，只需把域名换成 `llm.ziy.cc`、密钥换成 KUNPO 的 `sk-` 密钥。

## 接口地址

```
POST https://llm.ziy.cc/tripo/v3/generation/text-to-model        # 文生 3D
POST https://llm.ziy.cc/tripo/v3/generation/image-to-model       # 图生 3D（单图）
POST https://llm.ziy.cc/tripo/v3/generation/multiview-to-model   # 多视角生 3D（多图参考）
POST https://llm.ziy.cc/tripo/v3/generation/image-to-multiview   # 单图出四视角图
GET  https://llm.ziy.cc/tripo/v3/tasks/{task_id}                 # 查询任务
GET  https://llm.ziy.cc/v1/tasks/{task_id}/artifacts             # 列出产物
```

<Warning>
  这几个地址不走 `/v1/chat/completions`，也不走图像生成接口。
</Warning>

## 该用哪个接口

| 你手上有 | 用这个接口 | 说明 |
|----------|-----------|------|
| 一段文字 | `text-to-model` | 文生 3D |
| **一张**参考图 | `image-to-model` | 图生 3D。这个接口只接受一张图 |
| **多张**同一物体的不同角度图 | `multiview-to-model` | 多图参考的唯一入口，最多 4 张（前 / 左 / 后 / 右） |
| 一张图，但想先看四视角 | `image-to-multiview` → `multiview-to-model` | 先由模型补出四视角，再拿 `task_id` 复用出模 |

<Warning>
  **`image-to-model` 不支持多图参考，五个模型一个都不例外。** 无论把多张图放进 `input`、`images`、`files`
  还是 `inputs` 数组，上游都会返回 400 `file is required for image_to_model`。这是接口本身的限制，与模型无关，
  **`P2-20260801` 同样不支持**。要用多张图请走 `multiview-to-model`，见
  [哪些模型支持多图参考](#哪些模型支持多图参考)。
</Warning>

## 可用模型

| 模型名 | 说明 |
|--------|------|
| `v3.1-20260211` | 当前主力版本，几何与贴图质量最好 |
| `v3.0-20250812` | 上一版，参数与 3.1 相同，几何面数上限更低 |
| `v2.5-20250123` | 旧版本，仅在需要复现历史结果时使用 |
| `P1-20260311` | 低模专用，面数可精确控制，适合游戏资产；不支持 `quad` |
| `P2-20260801` | P1 的升级版，唯一支持四边面输出（`quad`）的版本，单价明显更高 |

### 哪些模型支持多图参考

**多图参考取决于用哪个接口，不取决于用哪个模型。** 五个模型的表现完全一致：

| 模型名 | `text-to-model` | `image-to-model`（单图） | `image-to-model` 传多图 | `multiview-to-model`（多图） |
|--------|:---------------:|:------------------------:|:-----------------------:|:----------------------------:|
| `v3.1-20260211` | 支持 | 支持 | **不支持** | 支持 |
| `v3.0-20250812` | 支持 | 支持 | **不支持** | 支持 |
| `v2.5-20250123` | 支持 | 支持 | **不支持** | 支持 |
| `P1-20260311` | 支持 | 支持 | **不支持** | 支持 |
| `P2-20260801` | 支持 | 支持 | **不支持** | 支持 |

换句话说：**没有任何模型能让 `image-to-model` 吃下多张图，而五个模型走 `multiview-to-model` 都能用多图出模。**
包括 `P2-20260801`——它并不因为单价更高就多一项多图能力。

<Note>
  `image-to-multiview` 也要求填写上表中的合法模型 ID（网关会校验），但**上游忽略该接口的模型选择**，
  实际总是用它自己的默认版本（任务回显 `model_version: "default"`）。所以这个接口填哪个模型都一样。
</Note>

<Warning>
  `model` 必须写上表中带日期后缀的完整 ID。像 `tripo-v3.1`、`v3.1` 这样的简写会直接返回 400。
  完整模型 ID 与单价可从 <a href="https://llm.ziy.cc/pricing" target="_blank">模型广场</a> 复制。
</Warning>

## 文生 3D

<CodeGroup>

      "texture": true,
      "pbr": true,
      "texture_quality": "detailed"
    }'
  ```

  import requests

  resp = requests.post(
      "https://llm.ziy.cc/tripo/v3/generation/text-to-model",
      headers={"Authorization": "Bearer sk-你的密钥"},

          "model": "v3.1-20260211",
          "prompt": "a small red wooden cube with carved patterns",
          "texture": True,
          "pbr": True,
          "texture_quality": "detailed",
      },
  )
  resp.raise_for_status()
  print("任务已提交:", resp.json()["data"]["task_id"])
  ```
</CodeGroup>

## 图生 3D

参考图放进 `input`，可以直接传本地图片的 Base64，也可以传图片 URL。

```bash
# 本地图片：直接传 Base64（推荐，网关会自动转存）
curl -X POST https://llm.ziy.cc/tripo/v3/generation/image-to-model \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"v3.1-20260211\",
    \"input\": \"$(base64 -i shoe.jpg)\",
    \"texture\": true,
    \"pbr\": true
  }"
```

<Note>
  **传 Base64 时网关会自动把图片转存到 KUNPO 图床**，再把公网地址交给上游，你不需要自己找地方放图。`data:image/jpeg;base64,...` 这种 data URL 同样可以。

  转存只对真实图片生效（PNG / JPEG / WebP / GIF），非图片内容会原样透传。
</Note>

也可以直接传 URL，此时不经过转存，**上游必须能直接抓到这个地址**：

```json
{ "input": "https://kunpoapiimg.ziy.cc/images/output/Image-GI/20260909/xxxx.png" }
```

<Warning>
  自带 URL 时注意：带防盗链的图床（例如 Pexels）会被上游判为「无法访问」，任务提交成功但随后失败（`error_code: 2020`）。拿不准就改传 Base64，让网关转存。
</Warning>

图生 3D 不吃 `prompt` / `negative_prompt` / `image_seed`，传了会被忽略。

<Warning>
  `input` 只接受**一个**字符串。要用多张参考图请看下一节。
</Warning>

## 多视角生 3D（多图参考）

同一物体的多个角度一起喂给模型，几何还原比单图准得多。视角图放进 `inputs`，每个元素是一个只有一个键的对象：

```bash
curl -X POST https://llm.ziy.cc/tripo/v3/generation/multiview-to-model \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"v3.1-20260211\",
    \"inputs\": [
      {\"front\": \"$(base64 -i front.jpg)\"},
      {\"left\":  \"$(base64 -i left.jpg)\"},
      {\"back\":  \"$(base64 -i back.jpg)\"},
      {\"right\": \"$(base64 -i right.jpg)\"}
    ],
    \"texture\": true,
    \"pbr\": true
  }"
```

规则（都是上游硬校验，网关会提前拦下并给出同样语义的报错）：

| 规则 | 说明 |
|------|------|
| 视角键 | 只能是 `front` / `left` / `back` / `right`。`top`、`bottom` 等一律报错 |
| `front` 必填 | 缺少正面视角会被拒绝 |
| 至少 2 个视角 | 只给 1 个视角请改用 `image-to-model` |
| 最多 4 个视角 | 同一视角不能重复 |
| 顺序 | 与数组顺序无关，只看键名 |

每个视角的值和 `input` 一样，可传 Base64 / data URL（网关自动转存图床）或公网 URL，两者可以混用。

<Tip>
  嫌 `inputs` 写起来麻烦，也可以传扁平的 `images` 数组，网关按 **`[front, left, back, right]`** 的顺序映射：

  ```json
  { "model": "v3.1-20260211", "images": ["<正面>", "<左侧>", "<背面>"] }
  ```

  等价于 `inputs: [{"front": ...}, {"left": ...}, {"back": ...}]`。
</Tip>

多视角出模同样忽略 `prompt` / `negative_prompt` / `image_seed`，其余参数（`texture`、`pbr`、`face_limit`、`quad` 等）与图生 3D 完全一致。

## 单图出四视角

只有一张图但想走多视角链路时，先用这个接口让模型补出四个角度：

```bash
curl -X POST https://llm.ziy.cc/tripo/v3/generation/image-to-multiview \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"v3.1-20260211\",
    \"input\": \"$(base64 -i shoe.jpg)\"
  }"
```

这个任务**不产出模型**，产出四张 1024×1024 的视角图，产物 key 就是 `front` / `left` / `back` / `right`（效果见 [效果示例](#效果示例)）：

```bash
curl https://llm.ziy.cc/v1/tasks/{task_id}/artifacts -H "Authorization: Bearer sk-你的密钥"
# → artifacts: [{"key":"front",...},{"key":"left",...},{"key":"back",...},{"key":"right",...}]
```

拿到之后不必把四张图再传一遍，**直接填这个任务的 `task_id` 复用**：

```json
{
  "model": "v3.1-20260211",
  "inputs": [{ "task_id": "task_kHTi3NXahVnZ3lRlGdkmFgAq6RdmL5b0" }],
  "texture": true
}
```

填的就是 `image-to-multiview` 返回的那个 `task_` 开头的 ID，网关会自动换成上游认的引用。计费与图生 3D 相同。

<Note>
  `inputs` 里带 `task_id` 时只允许这一个元素，不能和视角图混着传。
  被引用的任务必须是你自己的、已成功的四视角任务。
</Note>

<Warning>
  这个接口只接受 `model` 和 `input` 两个字段，`texture`、`face_limit` 之类的 3D 参数传了也没用——
  它出的是图，不是模型。上游甚至会忽略 `model`，按自己的默认版本生成。
</Warning>

```bash
curl https://llm.ziy.cc/tripo/v3/tasks/{task_id} \
  -H "Authorization: Bearer sk-你的密钥"
```

### 响应示例

```json
{
  "code": 0,
  "status": "success",
  "data": {
    "task_id": "task_xxxxxxxxxxxx",
    "type": "image_to_model",
    "status": "success",
    "progress": 100,
    "credits_consumed": 20,
    "created_at": "2026-09-09T04:35:47.552457Z",
    "completed_at": "2026-09-09T04:37:12.707544Z",
    "input": { "model_version": "v3.1-20260211", "texture": false, "pbr": false },
    "output": {
      "model_url": "https://tripo-data.rg1.data.tripo3d.com/...glb?Policy=...",
      "rendered_image_url": "https://tripo-data.rg1.data.tripo3d.com/...webp?Policy=..."
    }
  }
}
```

### 任务状态

`data.status` 沿用上游的小写取值：

| 状态 | 说明 |
|------|------|
| `queued` | 排队中 |
| `running` | 生成中，可读 `data.progress`（0–100 的数字，不是百分号字符串） |
| `success` | 完成，产物在 `data.output` |
| `failed` | 失败，原因见 `data.error_message` 与 `data.error_code` |

<Tip>
  建议每 5～10 秒轮询一次。实测无贴图的模型 2～4 分钟出结果，开贴图更久。
  只把 `success` 和 `failed` 当终态，其余一律继续等待。
</Tip>

<Note>
  请求里写的是 `model`，但任务回显里这个字段叫 `input.model_version`；`task_id` 由 KUNPO 签发（`task_` 前缀），
  与上游内部 ID 不同，查询和取产物都用 KUNPO 返回的这个。
</Note>

## 获取产物

`data.output` 里的地址是上游签名链接，**约 24 小时后失效**。推荐改用 KUNPO 的产物接口，由网关代取，不必自己处理上游签名：

```bash
# 1. 列出产物
curl https://llm.ziy.cc/v1/tasks/{task_id}/artifacts \
  -H "Authorization: Bearer sk-你的密钥"
```

```json
{
  "task_id": "task_xxxxxxxxxxxx",
  "artifacts": [
    {
      "key": "model",
      "type": "file",
      "mime_type": "model/gltf-binary",
      "content_url": "https://llm.ziy.cc/v1/tasks/task_xxxx/artifacts/model/content?access=..."
    },
    {
      "key": "preview",
      "type": "image",
      "mime_type": "image/png",
      "content_url": "https://llm.ziy.cc/v1/tasks/task_xxxx/artifacts/preview/content?access=..."
    }
  ]
}
```

```bash
# 2. 下载：带 access 参数可直接分发，带密钥则不需要 access
curl -L -o model.glb \
  "https://llm.ziy.cc/v1/tasks/{task_id}/artifacts/model/content" \
  -H "Authorization: Bearer sk-你的密钥"
```

| 产物 key | 出现在 | 内容 |
|----------|--------|------|
| `model` | 三个出模接口 | GLB 模型（glTF 2.0 二进制），开贴图后体积可达数十 MB |
| `preview` | 三个出模接口 | 512×512 的渲染预览图 |
| `front` / `left` / `back` / `right` | `image-to-multiview` | 四张 1024×1024 JPEG 视角图 |

<Note>
  `image-to-multiview` 的任务在 `data.output` 里把视角地址嵌在 `generate_multiview_image` 下
  （`front_view_url` 等），且没有 `model_url`。用 `/v1/tasks/{task_id}/artifacts` 就不用关心这层嵌套。
</Note>

## 轮询与下载示例

```python Python
import time
import requests

BASE = "https://llm.ziy.cc"
HEADERS = {"Authorization": "Bearer sk-你的密钥"}


def generate_3d(prompt, interval=8, timeout=900):
    resp = requests.post(
        f"{BASE}/tripo/v3/generation/text-to-model",
        headers=HEADERS,
        json={"model": "v3.1-20260211", "prompt": prompt, "texture": True, "pbr": True},
    )
    resp.raise_for_status()
    task_id = resp.json()["data"]["task_id"]

    start = time.time()
    while time.time() - start < timeout:
        data = requests.get(f"{BASE}/tripo/v3/tasks/{task_id}", headers=HEADERS).json()["data"]
        status = data["status"]
        if status == "success":
            break
        if status == "failed":
            raise RuntimeError(f"生成失败: {data.get('error_message')}")
        print(f"状态: {status} {data.get('progress', 0)}%")
        time.sleep(interval)
    else:
        raise TimeoutError("轮询超时")

    glb = requests.get(
        f"{BASE}/v1/tasks/{task_id}/artifacts/model/content", headers=HEADERS
    )
    glb.raise_for_status()
    with open(f"{task_id}.glb", "wb") as fp:
        fp.write(glb.content)
    return task_id
```

## 请求参数说明

<ParamField path="model" type="string" required>
  见 [可用模型](#可用模型)。必须写完整 ID。
</ParamField>

<ParamField path="prompt" type="string">
  文生 3D 必填，最长 1024 字符。图生 3D 忽略该字段。
</ParamField>

<ParamField path="negative_prompt" type="string">
  不希望出现的内容，最长 255 字符。仅文生 3D 有效。
</ParamField>

<ParamField path="input" type="string">
  图生 3D 与单图出四视角必填，参考图。**只接受一个字符串**，不接受数组。
  可传 Base64 / data URL（网关自动转存图床）或公网 URL，见 [图生 3D](#图生-3d)。
</ParamField>

<ParamField path="inputs" type="array">
  多视角生 3D 必填。元素为单键对象 `{"front": "<图>"}`，键取 `front` / `left` / `back` / `right`；
  `front` 必填、至少 2 个视角。也可以写成 `[{"task_id": "..."}]` 复用四视角任务的输出，
  见上文「多视角生 3D」一节。
</ParamField>

<ParamField path="images" type="array">
  `inputs` 的简写形式，按 `[front, left, back, right]` 顺序映射，最多 4 项。仅多视角生 3D 有效。
</ParamField>

<ParamField path="texture" type="boolean" default="true">
  是否生成贴图。关掉出白模，更快也更便宜。
</ParamField>

<ParamField path="pbr" type="boolean" default="true">
  是否生成 PBR 材质。`texture` 与 `pbr` 同时为 `false` 才算无贴图。
</ParamField>

<ParamField path="texture_quality" type="string" default="standard">
  `standard` / `detailed` / `extreme`。质量越高越贵。传其他值会被网关拒绝。
</ParamField>

<ParamField path="geometry_quality" type="string" default="standard">
  `standard` / `detailed`。`detailed` 面数更高、更贵。传其他值会被网关拒绝。
</ParamField>

<ParamField path="face_limit" type="integer">
  面数上限。P 系列可精确控制（48–20000）；H 系列按模型上限截断。
</ParamField>

<ParamField path="quad" type="boolean" default="false">
  输出四边面。**仅 `P2-20260801` 支持**，P1 传了会 400。
</ParamField>

<ParamField path="smart_low_poly" type="boolean" default="false">
  智能低模化。
</ParamField>

<ParamField path="generate_parts" type="boolean" default="false">
  拆分部件。v3.1 图生 3D 下与 `texture: true` 互斥，同时传会 400。
</ParamField>

<ParamField path="auto_size" type="boolean" default="false">
  按真实世界尺度自动缩放。
</ParamField>

<ParamField path="export_uv" type="boolean" default="true">
  是否导出 UV。
</ParamField>

<ParamField path="export_orientation" type="string">
  导出朝向，取 `+x` / `-x` / `+y` / `-y`。其他值会被网关拒绝。
</ParamField>

<ParamField path="orientation" type="string">
  模型朝向策略。
</ParamField>

<ParamField path="texture_alignment" type="string">
  贴图对齐策略。
</ParamField>

<ParamField path="compress" type="string">
  几何压缩，取 `geometry`。
</ParamField>

<ParamField path="model_seed" type="integer">
  几何随机种子，用于复现同一形状。
</ParamField>

<ParamField path="texture_seed" type="integer">
  贴图随机种子。
</ParamField>

<ParamField path="image_seed" type="integer">
  中间图随机种子，仅文生 3D 有效。
</ParamField>

<ParamField path="enable_image_autofix" type="boolean" default="false">
  自动修正输入图。
</ParamField>

<Note>
  上游对部分参数的校验比文档宽松：非法的 `orientation` / `texture_alignment` / `compress` 取值不会报错，
  而是被静默忽略并按默认值生成（**仍然计费**）。网关只对 `texture_quality`、`geometry_quality`、
  `export_orientation` 和模型名做了严格校验，其余字段请自行核对拼写。
</Note>

## 计费

按上游实际消耗的 credits 结算：提交时按参数预估并冻结额度，任务完成后用上游返回的真实用量多退少补。
影响单价的主要是模型、是否开贴图、贴图与几何质量档位。**任务失败会全额退回**。

关于多视角的两点：

- **`multiview-to-model` 与 `image-to-model` 同价**，视角数量不影响价格——传 2 张和传 4 张一样贵
- **`image-to-multiview` 固定 10 credits**，与模型、参数都无关

单价见 <a href="https://llm.ziy.cc/pricing" target="_blank">模型广场</a>。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| `unsupported model "..."` | 模型名写了简写 | 用带日期后缀的完整 ID |
| 提交返回 HTML 而不是 JSON | 路径写错 | 核对本页的四个地址 |
| 任务 `failed`，`error_code: 2020` | 上游抓不到图片 | 换成 KUNPO 图床或你自己可控的对象存储地址 |
| 提示 `data:` 不支持 | 传的内容没被识别成图片，原样透传给上游 | 确认是 PNG / JPEG / WebP / GIF 且 Base64 完整 |
| `quad` 报 400 | P1 不支持四边面 | 换 `P2-20260801` |
| `generate_parts` + 贴图报 400 | v3.1 图生 3D 下两者互斥 | 二选一 |
| 产物链接过期 | 用了 `output` 里的上游签名地址 | 改用 `/v1/tasks/{task_id}/artifacts` |
| `file is required for image_to_model` | 往 `image-to-model` 传了多张图 | 该接口只收一张，多图改走 `multiview-to-model` |
| `unsupported view "top"` | 视角键写错 | 只能用 `front` / `left` / `back` / `right` |
| `front view is required` | 缺正面视角 | 补一个 `front` |
| `at least 2 views are required` | 只给了 1 个视角 | 补视角，或改用 `image-to-model` |
| `origin task is unavailable` | `inputs` 里的 `task_id` 不是你自己的、或任务不存在 | 用自己账号下已成功的四视角任务 ID |
| `You have exceeded the limit of generation`（429） | 上游有并发生成上限，你的在跑任务太多 | 等前面的任务出结果再提交，别并发压 |

<Note>
  当前没有取消任务的接口，提交后只能等它跑完或失败。
  上游的文件上传接口（`file_token`）未开放代理，但不影响你用本地图片——把 Base64 放进 `input` 即可，网关会代为转存。
</Note>
